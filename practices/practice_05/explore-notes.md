# OpenSpec Explore — GET /tasks?tag

Цель фичи: добавить query-параметр `tag` к `GET /tasks`, который фильтрует задачи, где `tag` входит в список `tags` задачи (точное совпадение, регистрозависимо). Если параметр отсутствует — поведение без изменений.

## 1) Что уже есть в коде по теме
- FastAPI-приложение (`app/main.py`).
- Модели:
  - `TaskIn(title: str, tags: List[str])` с валидацией:
    - `title`: `strip`, непустой, длина ≤ 100.
    - `tags`: список 1..5; каждый тег — `strip`, непустой, длина ≤ 20, только `[A-Za-z0-9-]`.
  - `Task(id: int, title: str, tags: List[str])` — возвращаемая сущность.
- In-memory хранилище: `_tasks: List[Task]`, автоинкремент `_next_id`.
- Роуты:
  - `POST /tasks` — создаёт задачу (201) или 422 при невалидных данных.
  - `GET /tasks` — сейчас всегда возвращает весь список `_tasks` без фильтрации.
  - `DELETE /tasks/{task_id}` — удаляет по `id`, 404 если нет.
- Никакой нормализации регистра тегов при сохранении нет — теги хранятся как пришли (регистрозависимо).
- Фронт статика смонтирована, но фильтра по тегу в UI нет (и не требуется этой фичей).

## 2) Спорные моменты / вопросы для уточнения
- Пустой `tag` в query (например, `?tag=` или только пробелы): что делать? 400/422 или трактовать как «без фильтра»?
- Несколько тегов: поддерживаем ли `?tag=a,b` (через запятую) или несколько повторов `?tag=a&tag=b`? В задаче указан один параметр `tag` — трактовать как строго один.
- Регистр: указано «точное совпадение, регистрозависимо» — значит `Tag` ≠ `tag`. Подтверждаю: так и делаем.
- Нет совпадений: возвращать `200 OK` с пустым `[]`? (предлагаю да).
- Тримминг пробелов у query `tag`: делать `strip()` для параметра запроса перед сравнением?

## 4) Предлагаемые границы change и условия приёмки-кандидаты
Границы изменения (scope):
- Только бэкенд в `app/main.py`: обновить обработчик `GET /tasks`, добавить необязательный `tag` (query) и фильтрацию по точному вхождению в `Task.tags`.
- Не менять модели, валидацию POST, формат ответов и порядок элементов (сохраняем текущий порядок — по вставке).
- Не трогать фронт/статик и не менять `docs/requirements.md`, `docs/design.md`, `scripts/check.sh`.
- Добавить автотесты (новый файл в tests/) — в этой разведке не реализуем, только обозначаем.

Условия приёмки (кандидаты):
1) `GET /tasks` без `tag` возвращает полный список задач (как сейчас), `200 OK`.
2) `GET /tasks?tag=X` возвращает только те задачи, у которых `"X"` точно содержится в `tags` (регистрозависимо), `200 OK`.
3) При отсутствии совпадений возвращается `200 OK` и пустой массив `[]`.
4) Порядок задач в ответе не меняется относительно текущего (вставочный).
5) Невалидный `tag` (например, пустой после `strip`) — поведение по решению: либо `400 Bad Request` (предпочтительно), либо трактовать как «без фильтра». Требует подтверждения.
