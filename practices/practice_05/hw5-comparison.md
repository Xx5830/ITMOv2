# ДЗ 5: две команды - одна фича (поиск задач по названию)

Фича: `GET /tasks?q=` (API) + поле поиска (UI) в проекте `practices/practice_04/project`.

| | Команда логики | Команда UI |
|---|---|---|
| Фреймворк | GitHub Spec Kit | OpenSpec |
| Спека до | `specs/002-title-search/spec.md` (+ plan, tasks, research, data-model, quickstart) | `openspec/changes/search-tasks-ui/` (proposal, spec delta, design, tasks) |
| Спека после | та же, правки человека: убран выдуманный SC-002 про «1 секунду», SC-001 привязан к тестам | основная спека `openspec/specs/task-search-ui/spec.md` после архива |
| Кто писал | агент GPT-5 через OpenCode (`/speckit.specify`, `plan`, `tasks`, `implement`) | Claude напрямую |
| Реализация | `app/main.py`, `tests/test_title_search.py` | `app/static/index.html` |

## Общий контракт
`specs/002-title-search/contracts/search-contract.md`. Что согласовано до кода:
1. Фильтрация только на сервере.
2. UI не шлёт пустой `q`, сервер всё равно отвечает 400.
3. Дебаунс 300 мс.
4. **Кеш localStorage пишется только для ответа без `q`**: найденный конфликт со старой фичей B,
   иначе после сбоя сети UI показал бы результат поиска как «весь список».
5. Состояния UI: пусто, загрузка, найдено, ничего не найдено, 400, сбой сети.

Агент Spec Kit при `/speckit.plan` переписал контракт и потерял пункты 2-5; человек вернул согласованную версию,
версия агента сохранена как `contracts/api-contract.md`.

## Сравнение фреймворков
| | OpenSpec | Spec Kit |
|---|---|---|
| Единица работы | change (изменение существующей системы) | feature (спека новой функции) |
| Артефакты | proposal, spec delta, design, tasks; потом архив в основную спеку | spec, plan, research, data-model, tasks, checklists |
| Проверка | `openspec validate --strict` проверяет структуру | чеклист качества спеки, `/speckit.analyze` |
| Жизненный цикл | есть `archive`: дельта вливается в живую спеку | архива нет, спеки лежат по фичам |
| Вес | лёгкий, хорошо для brownfield | тяжелее, много файлов, больше шагов |
| Конституция | нет, правила в `config.yaml` | отдельный `constitution.md`, сверка в плане |
| Риск | валидатор не проверяет смысл | агент добавляет лишнее (SC-002) и меняет чужие файлы (контракт) |

Вывод: для маленьких правок существующего проекта OpenSpec быстрее и чище; Spec Kit даёт больше структуры
для новой фичи с нуля, но требует жёсткого человеческого ревью выдачи агента.

## Рефлексия
- **Согласовали:** серверный поиск, 400 на пустой `q`, дебаунс, кеш только для не-поисковых ответов.
- **Чему научились:** общий контракт нужно держать в отдельном файле и защищать от переписывания агентом;
  агент без запроса добавил метрику («95% быстрее 1 с»), которую нечем проверить;
  в чужом чате агент подтягивает черновик из репозитория, поэтому «независимая» спека оказалась копией моей.
- **Отклонение:** UI реализован не рабочим агентом, а Claude напрямую; спека UI тоже написана Claude, а не отдельной командой.
